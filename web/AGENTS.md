# Web

## Purpose
React 19 + TypeScript + Vite PWA frontend using the ky-ui suite theme catalog (Busnes light/dark defaults plus every named suite and base theme), client-side WebCrypto PoW CAPTCHA, and administrative management panels.

## Ownership
Owns user interface components, service worker caching, PWA installation manifests, and frontend theme switching.

## Local Contracts
- `MemberHome.tsx` is the non-admin page: account name (its `h1`), an "Open chat" link (new tab, `rel="noopener noreferrer"`) to `/api/settings` `chat_url` when set, otherwise the "Chat isn't available yet." notice, and sign out. Non-admins get `AppHeader` (sign out) with two navigation rows, Home (tab `dashboard`, this page) and Appearance; tested by `MemberHome.test.tsx` and `AppHeader.test.tsx`.
- The header, login page and Overview show `/api/settings` `app_name` (the admin's name, else `KY_APP_NAME`); a 64-character name wraps (`.app-brand`, the login `<h1>`) and never widens the shell. Document title and manifest use KyMessages. The current embedded
  shell is the operator console; do not imply a successful backup/crypto review from static dashboard text.
  Retain suite icon masters and existing theme choices.
- Web themes default to the Busnes.app cream/light and charcoal/dark palettes with orange accents, following the OS until a browser-local choice is saved. Preserve existing named themes and saved choices.
- A signed-in user with `must_change_password` sees only password replacement and sign-out. Replacement uses `secureFetch`, returns to login after session revocation, and never exposes the normal navigation before completion.
- Strict TypeScript type safety without unused imports.
- `LicenseFooter.tsx`, last in the sidebar (`AppHeader`), renders ky-ui `shell.css`'s licence line and About dialog: "© <year> · MIT License" opens a native `<dialog class="ky-about">` named "About KyMessages" with a `v<app_version>` pill (from signed-in `/api/settings`; none without it), "Developed by Busnes.app", the outlined Close and `src/mit.txt`, which must equal `LICENSE.txt` (`web/license_test.go`, `LicenseFooter.test.tsx`). Its backdrop is the shell's plain dimmed one; no dialog blurs the page.
- The authenticated shell uses a persistent 240px sidebar (`--ky-sidebar-size`, 40px rows) matching KyCalendar's shell; the selected page is the shared ky-ui tinted pill with an accent rail (`navigation.css`; nothing overrides its fill), with a horizontal overflow navigation under the brand row on small screens. The account region below the navigation is ky-ui's `.ky-user`: the name over the role ("Administrator" or "Everyday account"; a display name equal to the role shows the username instead) and a labelled Sign out with lucide `LogOut` at 16px (`AppHeader.test.tsx`). The built-in stamp (`.ky-mark-stamp`) is inverted to a light tile in dark schemes in the sidebar and on sign-in; an uploaded logo (`/api/settings` `logo_custom`, true unless the server says false) never is.
- Composition follows the ky-ui design contract through shared tokens: every page head is `components/PageHead.tsx`, ky-ui's `.ky-page-head` (the one `h1`, an optional one-line lede and the page's action on the right) inside `.dr-page`, which sits on the suite's 32px gutter beside the sidebar. A bare `button` is the primary action, at most one per view, and other actions use `.btn-secondary`, `.btn-ghost` or `.btn-danger` (outline). Controls are `--ky-control-size` tall with `--ky-field-border` (≥ 3:1); every focusable element gets the global 2px `:focus-visible` ring, drawn on the border for fields so it reads as one ring. Orange marks only the primary action, selection and focus; warnings use `--warning`. The global button hover, active and disabled rules are wrapped in `:where(button, .btn)`, so shell controls (`.ky-user-signout`, `.ky-about-close`, `.ky-menu-*`) keep their own states, and the hover excludes `.ky-nav-item`, so a navigation row hovers to the neutral ky-ui surface, never the accent; `ui.spec.mjs` asserts idle-row hover contrast ≥ 4.5:1 and an unchanged selected row under the pointer in every browser project. A ⋯ menu is `components/MoreMenu.tsx` (a native popover of `role="menuitem"` buttons; arrow keys move, Escape closes).
- Themes: `src/theme.ts` adapts ky-ui 0.6.0 `themes.js`, six light/dark pairs. The saved `ky_theme` value is `system` (Busnes following the OS), a pair ID (that pair following the OS) or a half ID (a fixed mode); earlier IDs and aliases resolve to their half (`nord` is Nord Dark, `patina` is Ky Dark) and removed palettes (`cyber`, `oled`, `sky`, …) fall back to `system`. Choosing sets `data-theme` to the resolved half and `data-scheme` to its scheme, and `applyThemeVariables` sets a named palette inline, status colours included (cleared for Busnes and system). The shell carries no theme select (owner decision 2026-10-26); only the sign-in page keeps one, grouped by pair.
- `src/pages/Appearance.tsx` (tab `appearance`, every signed-in role, last in the navigation, lucide `Palette`) is the theme page, after KyCalendar's: the page head (Match system follows the device, Light or Dark fixes the mode, saved in this browser only), then six pair cards, each a preview and a Match system / Light / Dark segment; all 18 are one native radio group, the selected segment is filled and carries a ✓, and focus is one ring on the segment.
- `errorText` (`api.ts`) turns a fetch that never reached the server into "<what failed>: the server could not be reached. Check the connection and try again."
- Authenticated state-changing requests use `secureFetch` so the CSRF cookie (`__Host-ky_csrf` on secure deployments without `KY_COOKIE_DOMAIN`, else `ky_csrf`) is mirrored into `X-CSRF-Token`.
- `TwoFactorSetup.tsx` ("Account security", its own group under the Settings page, apart from the server's sections) reads `/api/auth/me` and renders nothing for non-local accounts. Its state (an Off or On badge) sits beside the action: off, the filled "Set up two-factor sign-in" shows the QR (`qrcode` `toDataURL`, a `data:` image the CSP allows) and the key, then confirms one code. The recovery codes from confirm are shown once, until "I have saved them". On: turning off takes a code or a recovery code. All calls use `adminFetch`; refused codes stay on the form (`TwoFactorSetup.test.tsx`).
- Register the service worker from the production JS bundle; keep `script-src 'self'` intact.
- The console has no device-pairing control for admins or members. Chat device sign-in and encryption-key verification belong to Element; the inherited console-session pairing API does not connect Matrix clients.
- `Login.tsx` is ky-ui's `.ky-auth` sign-in: the mark, the app name as `h1` and the one-line tagline "Team chat on your own server.", then one card. It labels its fields (`htmlFor`/`id`, `autoComplete` `username`, `current-password`, `one-time-code`); its error is `role="alert"`; the button is "Sign in" with lucide `LogIn`. Only when `/api/settings` `sso_enabled` is true (SSO on and a KyIdentity issuer set) does one KyIdentity link, exactly "Continue with Single Sign On", follow under a divider. `ChangePassword.tsx` uses the same frame. `CaptchaWidget` (`.ky-auth-check`) fetches and solves one challenge per mount, again when `round` changes (Login bumps it after every attempt: the server spends the token before checking the password) and on expiry (never sooner than a minute); never per render (`Login.test.tsx`).
- `App.tsx` validates `/api/auth/me` and `/api/settings` with `parseUser`/`parseSettings` (`dto.ts`) and shows a failure as an alert. Sign-out leaves the console only after the server confirms it; a refusal or network error keeps the session and says "You are still signed in" (`App.test.tsx`). `ErrorBoundary` wraps the app (`main.tsx`) and each page (keyed by tab), so a render failure shows a message instead of a blank page.
- `SCIMAdmin.tsx` lists `GET /api/admin/scim/users` (validated by `parseSCIMDirectory`), shows load errors, and says whether `KY_SCIM_TOKEN` is set; it never shows or copies a token (`SCIMAdmin.test.tsx`).
- Worker caching is limited to the same-origin public shell, manifest and assets. HTML is network-first with offline fallback so deployments refresh; dynamic/auth routes stay uncached.
- `Backup.tsx` validates every reply at the HTTP boundary (`parseBackupStatus`, run, drill, schedule and pairing replies; a malformed status is an error alert, not a blank page) and displays the
  recorded outcome independently of the older remote receipt. A non-empty `scheduler_error` is an error banner; its absence is normal. Pinning a key by hand asks `window.confirm` with the key ID (`recoveryKeyID`: hex SHA-256 of the decoded key, as the server derives it) and the k-of-n split; a first pairing (no key pinned) asks before KyRecovery's key is pinned and names the pinned key after. Local-only results,
  scheduled failures, partial success and unknown history must remain distinguishable. Success green marks only copies that exist and a schedule that can run: an empty directory, an unreported copy list and a schedule without a key or destination are neutral.
- Admin calls that need a fresh sign-in use `adminFetch` (`api.ts`): a 403 `reauthentication_required` opens the single `ConfirmItsYou` dialog (mounted in the admin shell), which links a same-origin `/api/sso/` `reauth_url` in a new tab and retries only on the admin's Retry; Cancel returns the refusal. Concurrent refusals share one answer. A POST is never replayed after a redirect. Admin DTOs are validated with the `dto.ts` helpers.
- With Matrix off, Users, Agents and Rooms render `ChatNotSetUp`: the tested sentence "Chat (Matrix) is not set up on this server." and a pointer to `matrix-init` and docs/CHAT-SETUP.md.
- `Users.tsx` lists Matrix users (search, paging) and ends a user's sessions one by one (End all runs the per-session finish route in server order and stops when step-up is refused). It has no lock/unlock: access is controlled in KyIdentity. Its note saying so is information, styled `dr-alert-info` (neutral); the warn and error tones are for things that need action. With Matrix off it says chat is not set up.
- `Agents.tsx` (admin nav `agents`, after Users) drives `/api/admin/agents`: list (owner, device, last used or "unknown" with the error, token state, Locked), `expiresInDays` (pure, vitest-tested) flags active tokens idle `idle_days - 14` days or more. Create shows `AGENT_WARNINGS` inline with Create/Cancel (Cancel sends nothing) and checks `^agent-[a-z0-9-]{1,32}$`; create and rotate open a native `<dialog>` with the token, the OpenClaw/Hermes blocks (Copy), Download skill and install steps, and drop the token from state on close; the token never goes to a URL, storage, log or error. Revoke is one click; Delete needs an inline confirm. All through `adminFetch`; replies validated (`parseAgents`, `parseAgentToken`); Matrix off says chat is not set up (`Agents.test.tsx`).
- `Rooms.tsx` (admin nav `rooms`, between Agents and Health) lists Matrix rooms (search, paging 50; column "State events", never messages) and opens a detail panel with members. Close is final (no Reopen) behind an inline confirm; delete requires typing the server-supplied `confirm_text` exactly and sends it for the server to re-check, and says it purges the room's history while its media (attachments, avatars) stays in the media store. Both use `adminFetch`, then poll `delete-status` (every `pollMs`, at most 90 polls; 3 failed reads in a row stop it) until Synapse ends the job; a running job found on open disables changes, and a 409 refusal re-reads the room so the running job is shown and followed, and the refusal is cleared. DTOs validated with `dto.ts`; Matrix off says chat is not set up.
- `Backup.tsx` warns for as long as `database_driver` from `/api/backup/status` is not `sqlite`: only the SQLite path can snapshot a database into a capsule, so a Postgres deployment makes no capsules at all.
- `Backup.tsx` shows `capsule_size` (highlighting `warning` at 75% of the limit) and, with Matrix, `media_last_run` and its read error, beside the capsule attempt.
- `Dashboard.tsx` (Overview) leads with the chat state ("Chat is not configured" with what to run, else "Chat is ready" or how many items need attention), then a compact readiness checklist: Chat connection (from the Matrix components of `/api/admin/health`), Users, Backups and, with Matrix, KyIdentity sync (`syncCard`: ok, "Needs attention: <first hint>" in the `dr-warn` tone, or failing since). Each row shows its state and its next action (sentence case); the one filled button goes on the most severe row (warning or worse), the rest are secondary, and with Matrix off the Users action is a quiet text link. With Matrix off the chat row is "Not configured" and its action "Set up chat" opens `docs/CHAT-SETUP.md` on GitHub in a new tab (`noopener noreferrer`); the others call `onNavigate('health'|'users'|'backup'|'settings')`. Console health (the non-Matrix components) is its own line under the checklist. Each source fails alone; with Matrix off there is no sync row, and a sync-status request that never reached the server adds none either.
- `Settings.tsx` shows the `db_driver` from `/api/settings` and warns whenever it is not `sqlite` (the supported target is SQLite on one instance; Postgres gets no capsules); it never claims Postgres support (`Settings.test.tsx`). Its title matches the navigation ("Settings"). Its sections (Database, `BrandingPanel`, `SyncPanel`, `FederationPanel`, `NotesPanel`) sit flat in `.dr-settings` at a 46rem form width, divided by rules, never boxed inside each other; Account security, passed in by `App.tsx` as children, follows as its own group. Branding: name (Save name, and beside it "Use default name (<KY_APP_NAME>)"), one "Upload logo" button whose file choice uploads (`image/png`, refused over 1 MiB before sending), and, only while a custom logo is stored, a ⋯ menu with "Reset logo", all through `adminFetch`; the preview is `/app-icon.png?v=<sha256>` or `?v=default`, never a `blob:` URL (CSP `img-src 'self' data:`); `elementNotice` says what Element's file holds while it differs (with the error when there is one), prefixed "Saved, but" only right after a change; Element's `brand`, `served` and errors are clipped, never refused, so a hand-edited file cannot hide the panel; `staleServed` gives the brand a running Element still serves once the file is right, shown as "Element shows “<served>” until it restarts: <`element.restart_hint`>" (the server's command in `<code>`, omitted when empty); `onBrandingChanged` makes the shell re-read `/api/settings`. Sync: nothing with Matrix off; last accepted webhook, rejections since restart, last sweep, hints (one `p.dr-hint` each) and an https-only KyIdentity link. A rejection counts toward warnings and hints unless a webhook was accepted after it; `bad_signature`, `not_configured` and `username_conflict` warn, the others only hint. `syncState`, `syncHints` and `syncCard` are pure and vitest-tested; hints are computed here, never on the server.
- `FederationPanel.tsx` (in `Settings.tsx`, after `SyncPanel`; nothing with Matrix off) drives `/api/admin/federation`: a radio group of the three levels; choosing a wider one first shows `wideningWarnings(level)` inline with Allow/Cancel (Cancel sends nothing), narrowing applies at once. "Your server" with Copy; at `manual`/`curated` an add field (the server normalises the name), the server list with a status badge and hint from `/api/admin/federation/status` (fetched after load and on "Check connections", never blocking the page) and Remove; at `curated` the public-server checkboxes with an "Open sign-up" badge, or "No public servers are listed in this release yet." After any change it shows "Restart Synapse to apply: <`restart_hint`>"; while `unapplied` (required in the DTO) is non-empty it shows instead, as an alert, that removed servers can still federate until Synapse restarts, naming them; `file_error` shows as an error. All changes use `adminFetch`; DTOs are validated (`parseFederation`, `parseStatuses`); `FederationPanel.test.tsx`.
- `NotesPanel.tsx` (in `Settings.tsx`, after `FederationPanel`; nothing with Matrix off) reads `/api/admin/notes` (`parseNotes`). Not available: how to set it up (re-run `matrix-init`, add `docker-compose.notes.yml`), no buttons. Otherwise the bot account, when it last checked in, and the switch: Turn on first shows `NOTES_WARNINGS` inline with Turn on/Cancel (Cancel sends nothing); Turn off is one click; both through `adminFetch` (`NotesPanel.test.tsx`). While notes are on it also shows "Shared-screen snapshots" (Allowed/Off) with its own `Switch`: on behind `SCREENS_WARNINGS`, off in one click (`/api/admin/notes/screens/{enable,disable}`).
- `Rooms.tsx` Close copy: when the room's `remote_members` (joined from other servers) is above zero, Close says it removes this server from the room and other servers keep it, not "cannot be reopened"; Delete says other servers keep their copies.
- `Health.tsx` lists components from `/api/admin/health` (including `synapse-admin`, the console's Synapse admin access, shown without a version; status, version, Compose pin, error) and embeds `NetworkCheck`. A failed check clears the earlier report (status is unknown, never shown as a stale Up), and Check again remounts `NetworkCheck` so its marks are never older than the page. Versions render as text only; a `source` link is kept only when it is https under the upstream `element-hq` or `postgres` GitHub repos. `Audit.tsx` is a read-only, paged (50) view of `/api/admin/audit` filtered by kind (`auth|backup|branding|matrix|scim`); below 720px each record stacks as labelled lines (every field kept, explicit table roles); both validate DTOs with `dto.ts`.
- `NetworkCheck.tsx` renders on the admin-only Health page: it fetches `/api/admin/network-check`, validates the DTO at the boundary (a malformed or failed response shows `Network check unavailable.`), aborts on unmount and lists five Pass/Warn marks: trusted proxy peer, trusted `X-Forwarded-Proto: https`, https `KY_APP_URL`, host match, and `KY_TRUSTED_PROXIES` naming only single addresses (`trusted_proxies_narrow`), each with a status icon in `--success`/`--warning`. Tested by `NetworkCheck.test.tsx`.

## Verification
- Browser setup: build the frontend, run `go build -o .browser/server ./cmd/server` at the repo root, then `cd web && npx playwright install chromium firefox && npm run test:browser`. CI also installs browser OS dependencies.
- `make test-web` or `cd web && npm ci && npm test`, then `npm run build` (vitest with jsdom; `src/test-setup.ts` stubs the jsdom `<dialog>` methods; `src/pages/Backup.test.tsx` renders the recovery screen against a stubbed status route). Commit `web/dist` after a build; CI diffs it.

## Shared browser UI

- `src/ky-ui/` is generated from Busnes-app/ky-ui, pinned by `VERSION` file hashes. Change shared colors, navigation states and storage helpers upstream, then run its consumer sync with an explicit worktree map; do not hand-edit vendored files.
- Products own layout, routes, saved choice keys and named palettes. Busnes aliases consume shared tokens; mark primary navigation with `ky-nav-item` while preserving current-page semantics.
- Verify vendored files with `node src/ky-ui/check-vendor.mjs` from this document's directory. Builds/CI run that check. Rendered evidence and capture limitations are recorded in the repository-root `UI-VERIFICATION.md`.
