# KyMessages on the K80/K81 Cluster Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Yoshi runs KyMessages (app, Postgres, Synapse, MAS, Element) on K81 behind the HLUSWCK8 tunnel, isolated from the other seven Ky apps, signed in through KyIdentity and backed up to KyRecovery from day one.

**Architecture:**
- One code change in this repo: `KY_MATRIX_ELEMENT_RESTART_HINT` (default `docker compose restart element`) reaches the Settings restart hint through `GET /api/admin/branding` as `element.restart_hint`.
- Manifests and scripts in `/home/yoshi/git/busnes.app/ky-kubernetes` (not a git repo) translate `docker-compose.matrix.yml` one for one: five Retain local PVs on K81, six fixed-IP Services, five Recreate Deployments, a `matrix-init` holder pod, a zone policy set that `allow-suite` no longer covers, egress policies, an idempotent Cloudflare script and a two-mode operator wizard.
- Everything that touches the live cluster, Cloudflare or a human is a **CONTROLLER-RUN** gate (G0–G10, plus R for rollback). Gates are never dispatched to a subagent.

**Tech Stack:** Go 1.27 (stdlib only), React 19 + TypeScript + vitest; Kubernetes v1.37.1 with Cilium (policy enforcing, IPv4 pool `10.0.0.0/8`), containerd 2.3.5; bash, jq, curl, python3 (stdlib + PyYAML for local parsing), shellcheck; Cloudflare API v4.

**Spec:** `docs/superpowers/specs/2026-10-02-k8s-deploy-design.md` (binding). Cluster contract: `/home/yoshi/git/busnes.app/ky-kubernetes/AGENTS.md` and `README.md`. Suite contract: `/home/yoshi/git/busnes.app/AGENTS.md` (KyRecovery integration).

## Open questions for the controller

Each comes with a recommendation. The plan implements the recommendation; change the task if you decide otherwise.

1. **The app's identity.** The ruling keeps the app root with `DAC_OVERRIDE` so it can read the 0600 Matrix files and write Element's 0644 config owned by 10020. `fsGroup` cannot help: the kubelet would recursively chgrp the matrix volume and add group bits, which `matrix-init` refuses and which loosens every 0600 secret.
   - **Recommend:** run the app as `10020:10020` with every capability dropped. It then owns what it reads and the one file it writes, needs no capability, and a container escape lands as 10020 rather than root. `prepare-storage` makes `kymessages` and `kymessages-backups` 10020-owned too.
   - Fallback (the ruling): pod `runAsUser: 0`, `runAsNonRoot` removed, container `capabilities: {drop: [ALL], add: [DAC_OVERRIDE]}`, and `prepare-storage` leaves those two directories root-owned 0700.
   - Consequence for a future cluster restore: `data/` and `backups/` stay owned by 10020 (Compose chowns them to root because its app runs as root). Task 6 writes this into the runbook.
2. **MAS's admin bind.** `mas.yaml` binds the admin listener to the host `mas-admin`. In the cluster that name is a Service VIP, which MAS cannot bind.
   - **Recommend:** pod `hostname: mas-admin`, so `/etc/hosts` resolves it to the pod IP first. Isolation of 8081 then rests on the zone policy (only the app may reach it), as Compose's rests on the `matrix-admin` network.
   - Fallback if G6 shows MAS failing to bind: a `matrix-init` change rendering the admin bind from an env var. That is a new code task, and it reopens the Compose contract.
3. **MAS → Synapse is missing from the spec's allow list.** MAS calls `http://synapse:8008/_synapse/mas/…` to provision users and check localparts. Without that edge, first sign-in fails. **Recommend:** add the edge (Task 3) and amend the spec's Section 2 in the same PR as Task 1.
4. **The offboarding gate cannot disable Yoshi.** KyIdentity refuses to disable the last active administrator, and Yoshi is presumably that administrator.
   - **Recommend:** prove offboarding by **unassigning** Yoshi from the chat app and reassigning him. The acceptance run proves that unassigning refuses a live token within 30 s and locks without deactivating.
   - Unlock on reassignment is **unproven**; G9 measures it. If the controller wants the literal disable path, a second KyIdentity administrator must exist first.
5. **KyRecovery service name.** The spec says "service `kymessages`". The claim pins whatever `KY_APP_NAME` says (`KyMessages`) and overwrites the generate-time name. **Recommend:** generate the code with service name `KyMessages`, so both screens agree, and keep `KY_APP_NAME` at its default.
6. **Where the directory chown lives.** The plan follows the ruling: the shared `prepare-storage.json` pod creates the five directories and gains `CAP_CHOWN`, and it skips directories that are already correct, so it is safe to re-run. A separate one-off pod would keep the shared one at drop-ALL. **Recommend:** keep the ruling. The pod runs once and is deleted.
7. **`KY_TRUSTED_PROXIES`.** cloudflared's pod IP changes on every restart and could reschedule to K80. **Recommend:** `10.0.0.0/8`, the Cilium pod pool. This is safe because the zone policy admits only cloudflared to the app on 8080; node-originated probes send no `X-Forwarded-For`.
8. **No DNS override.** Compose's `KY_DNS` overlay exists for hosts that only a LAN resolver knows. Public DNS already answers `kyrecovery.urlxl.us` with `192.168.1.91`, and CoreDNS forwards upstream. KyMark already deposits this way. **Recommend:** no override.
9. **Read-only root filesystems.** All five containers get `readOnlyRootFilesystem: true` with `emptyDir`s at the paths the images write (facts table).
   - Postgres, Synapse and MAS under a read-only root are **unproven** until G6.
   - **Recommend:** if one fails to start, set that one container to `false`, record why in `kymessages.yaml`, and continue.
10. **The bootstrap password in the Secret.** It is used once, on an empty database, and then replaced in the console. **Recommend:** remove `KY_ADMIN_PASSWORD` from `kymessages-runtime` at G10 so no stale credential sits at rest.
11. **One wizard, two modes.** Operator work falls before `matrix-init` pass 2 (`identity`) and after the public routes exist (`live`). **Recommend:** one script, `setup-kymessages.sh identity|live`.
12. **Cloudflare through a script.** The ruling asks for exact curl calls. **Recommend:** put them in `kymessages-cloudflare.sh` (`snapshot`, `apply`, `verify`, `rollback DIR`). Every call is spelled out there, `apply` and `rollback` are idempotent and touch only what the script owns, and the gate re-runs `verify` after any change.
13. **Service links in the other apps.** New Service names inject env vars into five existing Deployments on their next restart (facts table). **Recommend:** accept. No prefix collides, and turning links off in those apps is out of scope.

## Review Focus

1. **The `allow-suite` change cuts an existing app off.** Every pod in `ky-stack` relies on it, and a selector typo (wrong key, `In` for `NotIn`) silently isolates all seven apps. Expected: each of the seven Services still answers a suite pod, and each public health path returns 200. Tests: Task 3 adds a seven-Service reach check to `verify-network.sh`; G2 and G9 run it; G9 runs the seven health URLs.
2. **A pod starts before `matrix-init` pass 2.** A `subPath` source that does not exist is created by the kubelet as an empty root-owned directory (Compose's `create_host_path: false` has no Kubernetes equivalent). `mas/config.yaml` would become a directory, and pass 2 would then fail. Expected: no zone Deployment exists until every `subPath` source is a regular file or directory. Tests: G5's source check gates G6; Task 4's validation confirms the `subPath` list matches the G5 list.
3. **The app cannot write Element's config.** A wrong uid, a read-only mount or the wrong `subPath` leaves the rename unsaved, and Settings shows the error forever. Expected: the app can write `/matrix/element/config.json`, and a rename appears in Element after `rollout restart deployment/element`. Tests: G6 runs `test -w`; G9 runs the rename round trip.
4. **The apex redirect swallows Matrix discovery.** The redirect phase runs before the tunnel, so a wrong expression sends `/.well-known/matrix/client` to GitHub and every client loses the homeserver. Expected: that path returns 200 JSON naming `https://msg-matrix.urlxl.com`, any other apex path returns 301 to GitHub, and `/.well-known/matrix/server` returns 404. Test: Task 5's `verify`, run at G7 and G9.
5. **KyIdentity cannot deliver the webhook or the back-channel logout.** Possible causes: KyIdentity's egress, its dial-time public-address guard, a wrong callback path, or the tunnel. Then offboarding silently never reaches MAS. Expected: KyIdentity shows Yoshi's delivery acknowledged, the console's sync panel shows an accepted webhook, and unassigning cuts a live Element session within 30 s. Tests: G8 stage 2, then the G9 offboarding check.

Also checked in the gates, because they are cheap and fatal:
- the Postgres volume is empty before first start (G2 prints its entry count) and both init scripts ran (G6 log check);
- the `kybackup` login works (G9 Health shows Postgres up);
- a `matrix-init` re-run needs `rollout restart` of every pod with a file `subPath` (the Task 6 runbook).

How the `subPath` mounts behave:
- A file `subPath` binds the inode present at container start, so a file renamed by `matrix-init` stays old in that container until its pod restarts.
- `element/config.json` is rewritten in place, so the app and Element see each write at once. Element still serves the copy it made at start, hence `rollout restart deployment/element`.
- A directory `subPath` (`synapse`, `mas`, `postgres`) sees renamed files immediately. Synapse and MAS read their config only at start anyway.

- [ ] **Step 1: Write the script**

```bash
#!/usr/bin/env bash
# KyMessages routing on the production tunnel HLUSWCK8, its urlxl.com DNS records and the apex
# redirect rule. Usage: kymessages-cloudflare.sh snapshot | apply | verify | rollback SNAPSHOT_DIR
# apply and rollback are idempotent and change only what this script owns. The token is read
# from cloudflare.env and reaches curl through a /dev/fd header file, never argv or output.
set -euo pipefail

state=${XDG_STATE_HOME:-$HOME/.local/state}/ky-kubernetes
account=4f80f219e311e7e2ac5312976759ccdb
tunnel=435cbb50-667d-4896-8dd2-42c4039bbb7d
zone=e4cf9b7aea56841f4b01b2d10ade4fba
apex_id=94df930834e51037cb5a3748f892b576
apex_before=github.com/yoshiofthewire
target=$tunnel.cfargotunnel.com
names=(msg.urlxl.com msg-matrix.urlxl.com msg-auth.urlxl.com msg-admin.urlxl.com)
rule_ref=kymessages_apex_to_github
cf=https://api.cloudflare.com/client/v4

token=$(sed -n 's/^CF_API_TOKEN=//p' "$state/cloudflare.env")
[[ -n $token ]] || { echo "no CF_API_TOKEN in $state/cloudflare.env" >&2; exit 1; }

# api METHOD PATH [BODY_FILE]: prints the response; fails on an HTTP error or success=false.
api() {
	local out args=(-sS --fail-with-body --proto '=https' --max-redirs 0 -X "$1")
	if (($# > 2)); then args+=(-H 'Content-Type: application/json' --data-binary "@$3"); fi
	out=$(curl "${args[@]}" -H @<(printf 'Authorization: Bearer %s\n' "$token") "$cf/$2") ||
		{ echo "Cloudflare $1 $2 failed: $out" >&2; return 1; }
	jq -e '.success == true' >/dev/null <<<"$out" ||
		{ echo "Cloudflare $1 $2 rejected: $(jq -c .errors <<<"$out")" >&2; return 1; }
	printf '%s\n' "$out"
}

# entrypoint FILE: saves the zone's redirect entrypoint to FILE and prints the HTTP status.
entrypoint() {
	curl -sS --proto =https --max-redirs 0 -o "$1" -w '%{http_code}' \
		-H @<(printf 'Authorization: Bearer %s\n' "$token") \
		"$cf/zones/$zone/rulesets/phases/http_request_dynamic_redirect/entrypoint"
}

# ours: the six tunnel rules, in route order.
ours() {
	jq -n '"ky-stack.svc.cluster.local" as $s | [
		{hostname: "urlxl.com", path: "^/\\.well-known/matrix/client$", service: "http://kymessages.\($s):8080", originRequest: {}},
		{hostname: "msg-matrix.urlxl.com", path: "^/_synapse/(admin|mas)/", service: "http_status:404", originRequest: {}},
		{hostname: "msg-matrix.urlxl.com", service: "http://synapse.\($s):8008", originRequest: {}},
		{hostname: "msg-auth.urlxl.com", service: "http://mas.\($s):8080", originRequest: {}},
		{hostname: "msg.urlxl.com", service: "http://element.\($s):8080", originRequest: {}},
		{hostname: "msg-admin.urlxl.com", service: "http://kymessages.\($s):8080", originRequest: {}}
	]'
}

snapshot() {
	local dir code
	dir=$state/cloudflare-backups/kymessages-$(date -u +%Y%m%dT%H%M%SZ)
	install -d -m 700 "$dir"
	api GET "accounts/$account/cfd_tunnel/$tunnel/configurations" >"$dir/tunnel-config.json"
	api GET "zones/$zone/dns_records?per_page=1000" >"$dir/urlxl.com-dns.json"
	jq -e '.result_info.total_count == (.result | length)' >/dev/null "$dir/urlxl.com-dns.json" ||
		{ echo 'DNS snapshot is incomplete' >&2; exit 1; }
	code=$(entrypoint "$dir/redirect-entrypoint.json")
	case $code in 200 | 404) ;; *) echo "redirect entrypoint: HTTP $code" >&2; exit 1 ;; esac
	printf '%s\n' "$code" >"$dir/redirect-entrypoint.status"
	chmod 600 "$dir"/*
	printf '%s\n' "$dir" >"$state/latest-kymessages-cloudflare.txt"
	echo "snapshot: $dir"
}

apply_tunnel() {
	local tmp
	tmp=$(mktemp -d)
	api GET "accounts/$account/cfd_tunnel/$tunnel/configurations" >"$tmp/now.json"
	ours >"$tmp/ours.json"
	jq --slurpfile ours "$tmp/ours.json" '
		def key: {hostname, path, service};
		$ours[0] as $o | ($o | map(.hostname) | unique) as $hosts
		| .result.config as $c
		| ($c.ingress | map(select((.hostname // "") as $h | $hosts | index($h)))) as $mine
		| if (($mine | map(key)) - ($o | map(key))) != [] then error("HLUSWCK8 already routes a KyMessages hostname elsewhere; resolve by hand") else . end
		| ($c.ingress - $mine) as $kept
		| if ($kept[-1] | has("hostname")) then error("the last ingress rule is not the catch-all") else . end
		| {config: ($c + {ingress: ($kept[:-1] + $o + [$kept[-1]])})}' "$tmp/now.json" >"$tmp/new.json"
	api PUT "accounts/$account/cfd_tunnel/$tunnel/configurations" "$tmp/new.json" >/dev/null
	rm -rf "$tmp"
	echo 'tunnel: KyMessages rules in place'
}

apply_redirect() {
	local tmp code
	tmp=$(mktemp -d)
	jq -n --arg ref "$rule_ref" '{ref: $ref, enabled: true,
		description: "urlxl.com apex to GitHub; Matrix discovery stays on KyMessages",
		expression: "(http.host eq \"urlxl.com\" and not starts_with(http.request.uri.path, \"/.well-known/matrix/\"))",
		action: "redirect",
		action_parameters: {from_value: {status_code: 301, target_url: {value: "https://github.com/yoshiofthewire"}, preserve_query_string: false}}}' >"$tmp/rule.json"
	code=$(entrypoint "$tmp/now.json")
	case $code in
	404)
		jq '{name: "default", kind: "zone", phase: "http_request_dynamic_redirect", rules: [.]}' "$tmp/rule.json" >"$tmp/body.json"
		api POST "zones/$zone/rulesets" "$tmp/body.json" >/dev/null
		;;
	200)
		jq --slurpfile rule "$tmp/rule.json" --arg ref "$rule_ref" \
			'{rules: ([.result.rules[]? | select(.ref != $ref) | del(.version, .last_updated)] + $rule)}' "$tmp/now.json" >"$tmp/body.json"
		api PUT "zones/$zone/rulesets/$(jq -r .result.id "$tmp/now.json")" "$tmp/body.json" >/dev/null
		;;
	*) echo "redirect entrypoint: HTTP $code" >&2; rm -rf "$tmp"; return 1 ;;
	esac
	rm -rf "$tmp"
	echo "redirect: $rule_ref in place"
}

apply_dns() {
	local tmp name rec
	tmp=$(mktemp -d)
	for name in "${names[@]}"; do
		rec=$(api GET "zones/$zone/dns_records?name=$name")
		case $(jq '.result | length' <<<"$rec") in
		0)
			jq -n --arg n "$name" --arg t "$target" \
				'{type: "CNAME", name: $n, content: $t, proxied: true, ttl: 1, comment: "KyMessages (ky-kubernetes)"}' >"$tmp/body.json"
			api POST "zones/$zone/dns_records" "$tmp/body.json" >/dev/null
			echo "dns: created $name"
			;;
		1)
			jq -e --arg t "$target" '.result[0] | .type == "CNAME" and .content == $t and .proxied' >/dev/null <<<"$rec" ||
				{ echo "dns: $name exists with another target; resolve by hand" >&2; return 1; }
			echo "dns: $name already in place"
			;;
		*) echo "dns: $name has several records; resolve by hand" >&2; return 1 ;;
		esac
	done
	rec=$(api GET "zones/$zone/dns_records/$apex_id")
	case $(jq -r .result.content <<<"$rec") in
	"$target") echo 'dns: apex already on the tunnel' ;;
	"$apex_before")
		jq -n --arg t "$target" '{content: $t}' >"$tmp/body.json"
		api PATCH "zones/$zone/dns_records/$apex_id" "$tmp/body.json" >/dev/null
		echo 'dns: apex now on the tunnel'
		;;
	*) echo 'dns: the apex points somewhere unexpected; resolve by hand' >&2; return 1 ;;
	esac
	rm -rf "$tmp"
}

apply() {
	[[ -s $state/latest-kymessages-cloudflare.txt ]] || { echo 'run snapshot first' >&2; exit 1; }
	apply_tunnel
	apply_redirect
	apply_dns
}

rollback() {
	local dir=${1:?rollback needs a snapshot directory} tmp name rec code
	[[ -s $dir/urlxl.com-dns.json ]] || { echo "not a snapshot: $dir" >&2; exit 1; }
	tmp=$(mktemp -d)
	api GET "accounts/$account/cfd_tunnel/$tunnel/configurations" >"$tmp/now.json"
	ours >"$tmp/ours.json"
	jq --slurpfile ours "$tmp/ours.json" '($ours[0] | map({hostname, path, service})) as $o
		| {config: (.result.config | .ingress |= map(select(({hostname, path, service}) as $k | $o | index($k) | not)))}' \
		"$tmp/now.json" >"$tmp/new.json"
	api PUT "accounts/$account/cfd_tunnel/$tunnel/configurations" "$tmp/new.json" >/dev/null
	echo 'tunnel: KyMessages rules removed'
	code=$(entrypoint "$tmp/entry.json")
	if [[ $code == 200 ]]; then
		jq --arg ref "$rule_ref" '{rules: [.result.rules[]? | select(.ref != $ref) | del(.version, .last_updated)]}' "$tmp/entry.json" >"$tmp/body.json"
		api PUT "zones/$zone/rulesets/$(jq -r .result.id "$tmp/entry.json")" "$tmp/body.json" >/dev/null
		echo "redirect: $rule_ref removed"
	fi
	for name in "${names[@]}"; do
		rec=$(api GET "zones/$zone/dns_records?name=$name&type=CNAME&content=$target")
		if [[ $(jq '.result | length' <<<"$rec") == 1 ]]; then
			api DELETE "zones/$zone/dns_records/$(jq -r '.result[0].id' <<<"$rec")" >/dev/null
			echo "dns: deleted $name"
		fi
	done
	jq --arg id "$apex_id" '{content: (.result[] | select(.id == $id) | .content)}' "$dir/urlxl.com-dns.json" >"$tmp/body.json"
	api PATCH "zones/$zone/dns_records/$apex_id" "$tmp/body.json" >/dev/null
	echo "dns: apex restored to $(jq -r .content "$tmp/body.json")"
	rm -rf "$tmp"
}

verify) verify ;;

esac
```
